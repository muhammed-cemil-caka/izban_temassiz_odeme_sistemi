IZBAN KIOSK R15 - WINDOWS 7 / EMBEDDED (x86)
============================================

!!! KURULUMDA ZORUNLU ADIM: BIDIRECTIONAL SUPPORT !!!
-----------------------------------------------------
Denetim Masasi -> Aygitlar ve Yazicilar -> termal yazici -> sag tik ->
Yazici ozellikleri -> Baglanti Noktalari (Ports) sekmesi ->
[X] Enable bidirectional support  ISARETLI OLMALI -> Apply

Bu kutu KAPALIYKEN Windows cihaza durumunu hic sormaz. Yazici "kapagim acik"
veya "kagidim bitti" dese bile durum bayraklari her zaman 0 gorunur, kuyruk
isi kabul eder ve kagit hic cikmaz - hicbir uyari almadan.

Alsancak otomatinda tam olarak bu oldu: yazici gunlerce "KAPAK ACIK"
bildiriyordu ama kimse duymuyordu. Kutu isaretlenir isaretlenmez sorun
saniyeler icinde ortaya cikti.

KAGIT CIKMIYORSA ILK BAKILACAK YER
----------------------------------
TANILA ekraninda "Durum bayraklari" satiri:

   0         -> cihaz sorun bildirmiyor
   16        -> KAGIT BITTI
   128       -> CIHAZ CEVRIMDISI
   4194304   -> KAPAK ACIK  (baski kafasi kilidi kapali degil)

4194304 goruyorsaniz: mekanizmadaki yesil kilit kolunu klik sesi gelene kadar
asagi bastirin, kagit rulosunu takin ve mekanizmayi otomattaki yuvasina tam
oturtun. Kapak sensoru govdeye duzgun oturmadan tetiklenmez.

NE VAR
------
- Termal yazici arizasi ARTIK KIOSKU DURDURMUYOR. Yazici bozuk olsa bile kart
  okuma ve bakiye gosterme calismaya devam eder.
- Ekranda "YAZICI TANILA" dugmesi: konsol olmadan, otomatin kendi ekraninda
  kurulu yazicilar / varsayilan yazici / spooler durumu / kuyruk raporu.
- Tanilama ekraninda "YAZICIYI YENIDEN BASLAT": ayar dosyasini duzelttikten
  sonra uygulamayi kapatmadan yaziciyi tekrar devreye alir.
- Kart okundugunda "BAKIYE FISI YAZDIR": gercek kart verisiyle gercek fis
  (kart no maskeli, NFC UID fise yazilmaz).
- Alt barda surekli yazici durumu gostergesi.
- Yerel islem gunlugu: Journal\kiosk-YYYY-AA-GG.jsonl (yalnizca takma kimlik).

NE ICIN?
--------
KioskPrint.dll bir Delphi/VCL kutuphanesidir ve yazici adi parametresi ALMAZ.
Belgeyi her zaman WINDOWS VARSAYILAN YAZICISINA gonderir. Otomattaki varsayilan
yazici termal yazici degilse (PDF/XPS/ag yazicisi), makbuz sessizce o kuyruga
gider ve kagit hic cikmaz.

Bu paket, yapilandirilan termal yaziciyi ilk vendor cagrisindan ONCE Windows
varsayilani yapar ve her makbuzdan once bunu yeniden dogrular.


GEREKSINIMLER
-------------
- Windows 7 / Windows Embedded, x86
- .NET Framework 4.0 Client Profile veya ustu (4.5 / 4.8 de olur)
- Termal yazicinin Windows'ta kurulu olmasi


KURULUM
-------
1. Bu klasoru otomata kopyalayin (ornegin C:\IZBAN-Yazici-Testi).
2. Klasor yapisi bozulmamalidir:

   IZBAN-Yazici-Testi\
     1-Yazicilari-Listele.bat
     2-Yazici-Teshis.bat
     3-Test-Fisi-Bas.bat
     4-Kiosk-Arayuzunu-Ac.bat
     IZBAN-Kiosk.exe
     KioskHardware.config.json      <-- yazici adi BURADA
     Bridge\                        <-- kopru + vendor DLL'leri


SIRAYLA YAPILACAKLAR
--------------------
ADIM 1 -> 1-Yazicilari-Listele.bat

  Otomatta kurulu yazicilarin gercek adlarini ve mevcut varsayilan yaziciyi
  gosterir. AUSKiosk.exe'yi KAPATMANIZA GEREK YOK.

ADIM 2 -> KioskHardware.config.json dosyasini Not Defteri ile acin

  "ThermalPrinterName" degerini, Adim 1'de cikan InstalledPrinters
  listesindeki adla BIREBIR ayni yapin.

  Pakette su an "Trentino Printer Driver 56mm" yaziyor. Bu bir SURUCU adina
  benziyor; Windows kuyruk adi buyuk ihtimalle farklidir. Mutlaka kontrol edin.

ADIM 3 -> 2-Yazici-Teshis.bat

  Cikis kodu 0 ise yazici hazir demektir. Degilse rapordaki alanlar
  hangi adimda takildigini soyler (bat dosyasi anlamlarini yaziyor).

ADIM 4 -> 3-Test-Fisi-Bas.bat

  Test fisini basar. DIKKAT: Bu islem Windows varsayilan yazicisini kalici
  olarak termal yazici yapar (KioskPrint.dll'in calismasi icin zorunlu).

  Cikis kodu 0 = is kuyruga verildi. YAZICIDAN KAGIT CIKTI MI, GOZLE KONTROL
  EDIN. API basarisi tek basina kagit ciktigini kanitlamaz.

ADIM 5 -> 4-Kiosk-Arayuzunu-Ac.bat

  Tam kiosk arayuzu: NFC + SAM + kart okuma + bakiye + fis. Bunun icin
  AUSKiosk.exe KAPALI olmalidir, aksi halde COM portu mesgul olur.

  Arayuz icinde:
    - Ana ekranda "YAZICI TEST FISI" ve "YAZICI TANILA" dugmeleri
    - Kart okutunca "BAKIYE FISI YAZDIR" dugmesi
    - Alt barda "YAZICI: HAZIR / HAZIR DEGIL" gostergesi
    - Yazici bozuksa bile kart okuma calismaya devam eder


BU SURUMDE CALISAN / CALISMAYAN ISLEVLER
----------------------------------------
CALISIR:
  - NFC okuyucu (COM4) + SAM dogrulamasi
  - Gercek Izmirim Kart kimligi ve bakiyesi okuma
  - Termal yazici: test fisi + gercek bakiye sorgulama fisi
  - Yazici tanilama ve yeniden baslatma
  - Yerel islem gunlugu

CALISMAZ (kod eksigi degil, dis bagimlilik):
  - Karta para yukleme  -> Izmirim Kart yazma yetkisi/lisansi gerekir
  - POS ile odeme       -> banka POS SDK entegrasyonu gerekir
  Tutar secme ekrani calisir ama "POS ENTEGRASYONU BEKLENIYOR" der;
  para cekilmez, karta yazma yapilmaz.


BILINMESI GEREKENLER
--------------------
- Adim 1, 3 ve 4 (yazici komutlari) NFC okuyucuya dokunmaz; AUSKiosk.exe acik
  kalabilir. Sadece 4-Kiosk-Arayuzunu-Ac.bat icin kapatilmasi gerekir.
- Bu paket SALT OKUNURDUR: kart yazma, para yukleme, bakiye dolum ve POS
  islemleri kapalidir. Eski veritabanina, sertifikalara ve ayar dosyalarina
  yazilmaz.
- Bridge calisirken Windows varsayilan yazicisi disaridan degistirilirse,
  KioskPrint.dll ilk kullanimda yakaladigi kuyrugu birakmaz. Kod bu durumu
  tespit edip yazdirmayi durdurur ve yeniden baslatma ister. Bridge surecini
  kapatip yeniden baslatin.
- Windows Embedded write filter (EWF/FBWF/UWF) acikken varsayilan yazici ayari
  yeniden baslatmada geri alinir. Kod her acilista ayari tekrar uyguladigi icin
  calisma kalicidir; ayarin kendisinin kalici olmasi isteniyorsa degisikligi
  filtre devre disiyken yapin.
